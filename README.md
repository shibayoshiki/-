# 教員マッチングアプリ

架空データを使うブラウザー内の試作です。デモIDで生徒・教員・管理者の画面を切り替え、ルールベースで教員を推薦します。Teams向けの相談申込文はコピーして、宛先と内容を確認してからTeamsに貼り付けます。B版では希望日時を文面に追加でき、面談の最終調整はTeamsで行います。

## ファイルと起動方法

| ファイル | 用途 |
| --- | --- |
| `index.html` | A版 v1.0。生徒の検索・推薦とTeams文面作成の入口 |
| `b.html` | B版 v1.0。A版の機能に加え、教員の予定表編集、生徒の予定表閲覧と希望日時の選択が可能 |
| `app.js` | A版・B版で共有する画面処理、保存、Teams文面生成 |
| `matching.js` | 共通の推薦ルールと相談目的別の暫定配点 |
| `teacher_A_v08_index.html` | 過去の比較用A版 v0.8 |
| `scripts/build-edition-b.mjs` | A版のHTMLからB版の入口を生成 |
| `tests/app.test.cjs` | 架空データを使うChromiumの回帰テスト |
| `tests/matching.test.cjs` | 架空データを使う推薦ロジックの単体テスト |

リポジトリ直下で静的HTTPサーバーを起動します。アプリの起動にNode.jsや追加パッケージは不要です。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

- A版は `http://127.0.0.1:8000/`
- B版は `http://127.0.0.1:8000/b.html`
- 比較用A版は `http://127.0.0.1:8000/teacher_A_v08_index.html`

デモIDは生徒が `S1001`、教員が `T1001`、管理者が `A1001` です。各版を同じブラウザーで開いても、保存データとセッションは版ごとに分かれます。A版は従来の保存キーを使用します。B版の予定にはデモ用の初期値があります。デモIDには本人確認機能がありません。実在する生徒・教員の情報は入力しないでください。

画面・スタイルの変更は `index.html` に加え、`node scripts/build-edition-b.mjs` でB版の入口を更新します。

## 動作検証

Node.js 20以降を使用します。テストはローカルサーバーと一時ブラウザーを起動し、架空データを使用します。

```sh
npm ci
npx playwright install chromium
npm test
```

既存のChromiumで検証する場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE` で実行ファイルを指定できます。テストではB版HTMLの生成差分、ログイン、大学名だけでの検索、Teams文面とクリップボード、B版の予定編集と希望日時、保存失敗と再試行、重複加点、分類削除時の参照整理を確認します。

手動で確認する場合は、生徒・教員・管理者の各デモIDを使います。A版では大学名だけを指定して検索し、申込文をコピーします。B版では教員が未来の予定枠を編集し、同じブラウザーの生徒画面で予定表を開いて希望日時入りの文面を生成します。分類変更の確認では、教員が架空項目を追加して削除申請し、管理者が承認します。生徒・教員の選択から削除対象だけが消えることを確認します。

分類と教員データは承認時にまとめて保存します。別キーに保存される生徒データは承認後に整理します。ブラウザーが一部の書き込みを拒否した場合、その項目は生徒画面で読み込み時に除外され、生徒が次に保存した際にストレージからも外れます。

## 推薦ルール

大学・学部・学科は、教員が登録した相談対応情報を1件ずつ照合します。推薦結果には一致・不一致と、評価に使った相談内容や経験を表示します。相談目的別の配点、判断根拠、架空事例での順位比較は[推薦ルールと暫定配点](docs/matching.md)を参照してください。
